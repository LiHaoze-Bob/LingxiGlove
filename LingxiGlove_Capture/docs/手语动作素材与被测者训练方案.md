# 手语动作素材与被测者训练方案

> 讨论 LingxiCapture 数据采集环节的"动作来源 + 被测者快速学习"问题，包含可选的素材方案与下一步待决策点。

## 一、动作来源（怎么定义"标准动作"）

当前默认 10 个 label 拆成两类：

| 类别 | label | 推荐来源 |
|---|---|---|
| 标准词 | 你好 / 谢谢 / 我们 / 来自 / 浙江 / 大学 | [中国手语在线词典](https://shouyu.ccrtvu.com/)（中央广播电视大学，公开免费，含视频） |
| 标准词（备选） | 同上 | [Spreadthesign](https://www.spreadthesign.com/zh.cn/) — 多语种手语词典，可对比中文/美式 |
| 自造词 | 灵犀 / 智能 / 手套 / 团队 | 团队自定义 + 自录 2–3 秒手机短视频，作为"标准答案"统一 |

**自造词建议**：

- "灵犀"：既可借用既有手势（如"心有灵犀"中的"心" + "通"），也可自造（双手指尖相对、向外摊开）。
- "智能"：可借用"智慧"+"机器/自动"组合手语；或采用国家通用手语中"智能"的标准打法。
- "手套"：可直接演示"戴手套"动作；或用国家通用手语词典查询。
- "团队"：标准词，可在词典中查到；多见于"团队、集体、组合"等多义近词。

> 落地动作：4 个自造词由你或队友先示范一次，用手机录短视频固定下来；此后所有数据采集都对齐这一份"标准答案视频"。

## 二、让被测者快速学习的方式

可以集成进 LingxiCapture，让 UI 里就能看到/学。三个方案选一：

### 方案 A — 本地 GIF/短视频卡片（推荐）

- 为每个 label 关联一个本地 GIF 或 ≤3 秒的 webm 短片
- LabelEditor 加路径字段（`mediaPath: string`），与 `labelNames` 一起存 localStorage
- RecordingHUD 角落贴小图，倒计时 Overlay 启动前先播 2–3 秒预览
- **优点**：离线可用、节奏稳、与采集流程无缝
- **成本**：需要先准备素材；要扩前端 UI

#### 素材命名约定（建议）

```
public/gestures/
  ├── 0_nihao.webm
  ├── 1_xiexie.webm
  ├── 2_women.webm
  ├── 3_lingxi.webm
  ...
```

WebM (VP9, 720p, ≤2 MB/段) 比 GIF 体积小 5–10 倍，浏览器可直接 `<video autoplay loop muted>` 播放。

### 方案 B — 外链词典跳转

- LabelEditor 双击改名时旁边加 🔍 按钮
- 点击 → `tauri::shell::open` 跳浏览器到 Spreadthesign / 中国手语在线 的搜索 URL
- **优点**：零素材成本
- **缺点**：要切窗口、网络依赖；自造词在外站搜不到

### 方案 C — 纸质动作卡 + 不改 UI

- 导出 10 个 label 的图文 PDF（外链词典截图 + 文字描述）打印贴墙
- UI 不动，开发零成本
- **缺点**：不如屏幕直观，无法与倒计时同步

### 方案 D — 暂不做

- 采集前由演示者口述 / 比划一遍即可
- UI 维持现状，等真要做培训时再扩

## 三、推荐路径

短期（演示阶段）：**方案 D + 自录 4 个自造词标准视频**，演示者口述 + 现场示范即可。

中期（要走真正的"被测者训练"）：**方案 A**，在 LabelEditor 里加 mediaPath 字段，倒计时前 2 秒先播预览。

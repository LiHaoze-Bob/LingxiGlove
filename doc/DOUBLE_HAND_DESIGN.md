## 1. 目标与非目标

### 1.1 目标（Goals）
1. **语义层目标**：将"相对运动学信息 ≠ 两只手独立识别结果之和"这一事实，显式建模到系统架构里，使得双手协同手势（如"朋友/冲突/帮助/比较"）在识别层可分。
2. **工程层目标**：在 **2 片 ESP32-S3（Nano ESP32 或 DevKit）** 的资源预算内完成双手采样、时钟对齐、双流推理。
   - 采样帧率 20 Hz（与 MVP `config.h` 的 `SENSOR_READ_INTERVAL = 50` ms 一致），**单帧处理必须 ≤ 50 ms** 才能不丢帧
   - 端到端时延（含云端往返，对需要云端的指令而言）目标 ≤ 500 ms（人对语音反馈的无卡顿感知阈值）
   - 上述两个预算**同时成立**：前者保证识别流水线不堆积，后者保证用户体验
3. **验证层目标**：每一项物理量（对齐误差、测距精度、识别 F1）都要有**可复现的实测脚本 + 数值区间**，而非口号。

### 1.2 非目标（Non-Goals）
- **不追求**连续句子的自由手语翻译。本白皮书只覆盖**孤立手势词 + 端云分级调用**。长句子由云端 Sign-Transformer 处理，属 P5 阶段 out-of-scope。
- **不追求**亚毫米级距离精度。D1 已诚实披露亚样本插值在 chirp 输入下有 ~1 样本本质偏置（见 §4.3），本版本**精度下限锁定 c/fs ≈ 7.15 mm**。
- **不覆盖** UWB、Vision、Leap Motion 等方案。这些方案在 SOLUTION_REVIEW §2.3 的候选表里已作对比，本白皮书只沿着"零增量硬件 + 声学 TDOA"这一条工程主线展开。

**角色分工（完整方案）**：
- **Master（右手）**：采样 + 推理 + 云端交互 + TTS 播报；挂 MAX98357A + 喇叭 +（待补）INMP441 麦
- **Slave（左手）**：采样 + 通过 ESP-NOW 上传 HandFrame；挂 MAX98357A + 喇叭 +（待补）INMP441 麦

"一主一从"拓扑有两个决策动因：
1. MVP 代码已经把 WiFi/HTTP/LLM/TTS 全部跑在右手主控上，新增 Slave 不触碰主链路
2. 右利手的主动作在右手，Master 承载语义推理更自然，左手仅做辅助特征

**测距链路选型（避免读者误读为单向架构）**：
- **本白皮书 v0.1 的最终设计目标**：**双向 RTT-TOF**。双方都具备发/收能力，
  一轮测距包含"Master 发 → Slave 收"和"Slave 发 → Master 收"两条路径，
  取两条 TOF 的**差分** `(t_MS − t_SM)/2` 可完全抵消跨板时钟偏差和固定收发延迟，
  这是物理上最稳健的相对距离观测。
- **当前 D1 仿真 / D2 POC 为简化起点**：只验证"一方发 / 另一方收"的**单向链路**，
  以独立验证 chirp 生成、定点相关器、CFAR 判据这三个原子能力。单向链路
  **无法给出绝对距离**（缺跨板同步），POC 只用作相对位移观测。
- **从单向 POC 到双向 RTT 的工程跨越**需要先补齐 INMP441 麦克风和跨板 GPIO 硬触发线，
  见 §7 D4 阶段。

## 3. Layer 1：时钟同步

### 3.1 问题陈述
两块 ESP32-S3 用各自的 240 MHz 晶振独立计时，`millis()` 最初并不在同一时钟域。20 Hz 采样下单帧窗 50 ms，要求跨板对齐误差 ≤ 5 ms（10% 帧窗），否则双手同帧的语义会错位。

### 3.2 设计：ESP-NOW + Master 打戳 + Slave EWMA

**数据面**：Slave 每 50 ms 采一帧，立刻 `SendHandFrame()` 推给 Master（`HandFrame` 结构见 §3.4）。Slave 在包里**不自行打时间戳**，只带单调自增 `seq_no`。

**时钟面**：Master 收到 HandFrame 的瞬间用**本机 `millis()`** 回填 `master_timestamp_ms`，再写入环形缓冲。这样"Master 时钟域"成为系统唯一基准，不需要跨板时钟校正。

**对齐**：Master 自采样一帧 `right_frame(t_r)` 时，在 Slave 环形缓冲里二分查找 `seq_no` 距离当前最近、且时间偏移 < 25 ms 的 `left_frame`，配对输出 `(left, right, Δt)`。

### 3.3 为什么选 ESP-NOW 而不是 WiFi UDP
- ESP-NOW **链路层直连**，不过 AP；Espressif 官方文档将其定位为"低延迟、适合实时控制"，
  但未公开给出具体的 P99 延迟数字（不同信道占用/距离/发射功率差异很大）。**本白皮书
  不引用任何虚构的"< 数 ms"断言**，真实延迟分布留 P2 双板实测后填入。
- ESP-NOW **无握手开销**，`send_cb` 能直接报告物理层 ACK 成败，方便丢包统计（当前
  `esp_now_sync.cpp` 的 `GetEspNowTxCount()` / `GetEspNowTxFailCount()` 已提供这个能力）
- 与 WiFi STA 共频，无需在双模式间切换（代码 `esp_now_sync.cpp` 已实现 STA + ESP-NOW 共存）

### 3.4 接口（A1 阶段已落地）
位置：`src/LingxiGlove_Main/esp_now_sync.h`

```cpp
struct __attribute__((packed)) HandFrame {
    uint32_t master_timestamp_ms;   // Master 侧回填；Slave 发送时为 0
    uint16_t seq_no;                // Slave 单调递增，循环至 65535
    uint16_t reserved0;             // 预留对齐位（当前恒 0）
    int16_t  ax, ay, az;            // IMU 原始 LSB，±2g full-scale
    int16_t  gx, gy, gz;            // IMU 原始 LSB，±250°/s
    uint16_t flex[5];               // Flex ADC 原始 0..4095
};
// sizeof(HandFrame) == 30 bytes （本机 clang++ -std=c++11 实测）
// offsets: ts@0  seq@4  rsv@6  ax@8  flex@20  end@30
// ESP-NOW 单包上限 250B，余量 220B 充足

bool InitEspNowSync(EspNowRole role, const uint8_t peer_mac[6]);
bool SendHandFrame(const HandFrame& frame);
void RegisterHandFrameHandler(HandFrameHandler handler);
```

**编译开关**：`ENABLE_ESPNOW_SYNC=0` 时整套代码零成本被剔除，MVP 单手行为不受影响。

## 4. Layer 2：感知 — 声学 TDOA 相对距离

### 4.1 问题陈述
IMU 只给加速度 + 角速度，二次积分得位置会在秒级别漂出米级误差，不能支撑"朋友（双手食指互勾，距离 ≈ 2 cm）"这类语义。需要**独立的相对距离观测量**。

### 4.2 方案：17–19 kHz chirp + 匹配滤波
- **信号**：5 ms 的 17–19 kHz 线性 chirp（加 Hann 窗抑制起止突变），归一化到 int16 峰值 28000
- **每一方的硬件**：MAX98357A + 喇叭（发）+ INMP441 I2S 麦（收），48 kHz 采样
- **接收侧算法**：在 30 ms 滑动窗口上做 int16×int16→int64 **朴素滑动相关**
- **距离推导**：相关 argmax 的样本号 `k*` → 飞行时间 `k*/fs` → 距离 `c × k*/fs`
- **精度下限**：`c/fs = 343/48000 ≈ 7.15 mm`（单样本量化地板，SNR → ∞ 也消不掉）

**发射节奏（设计目标 vs POC 现状必须分清）**：
| 时序口径 | 频率 | 说明 | 状态 |
|---|---|---|---|
| **白皮书 v0.1 设计目标** | 20 Hz（每 50 ms 一次） | 与 IMU/Flex 采样同频，识别层每一帧都有同期距离观测 | 设计层目标 |
| **D2 POC 当前实现** | 2 Hz（每 500 ms 一次） | `kTxIntervalMs = 500u`，POC 只验证发-收闭环，不追时序预算 | 已落地 |

从 500 ms → 50 ms 的工程改造需要三件事：① MAX98357A 连续喂 I2S 的缓冲编排、
② 相关器预算 ≤ 50 ms 窗口（目前 <3 ms，有 15× 余量）、③ 相邻 chirp 间最小静默时长
以避免多径残响。关于第 ③ 点——**17–19 kHz 的空气吸收不是主要制约**：按 ISO 9613-1
在 20 °C / 50 %RH 条件下，18 kHz 的空气吸收系数 α ≈ **0.4 dB/m** 量级（远小于早期
草稿误写的"6 dB/m"），因此 1.5 m 量程下直射波只衰减 <1 dB，可忽略；真正需要处理
的是室内**墙面/桌面多径回波**导致的伪相关峰，30 ms 采集窗 + CFAR 判据（见 §4.5）
已经压制了这一项。此时序优化 + 多径实证留在 **D3/D4 阶段**推进。

### 4.3 D1 实测数据：Python 仿真（500 次 Monte Carlo / 格子）
完整表格见 `doc/acoustic_tdoa_simulation_results.md`，下表节选代表性距离（0.1 / 0.5 / 1.0 / 1.5 m）：

| 真实距离 D | SNR=30 dB | SNR=20 dB | SNR=10 dB | SNR=0 dB | SNR=-10 dB |
|---|---|---|---|---|---|
| 0.10 m | 0.04 mm | 0.04 mm | 0.04 mm | 13.7 mm | 905 mm ⚠️ |
| 0.50 m | **0.21 mm** | **0.21 mm** | **0.21 mm** | 12.6 mm | 797 mm ⚠️ |
| 1.00 m | 0.42 mm | 0.42 mm | 0.42 mm | 13.1 mm | 740 mm ⚠️ |
| 1.50 m | 0.63 mm | 0.63 mm | 0.63 mm | 13.8 mm | 736 mm ⚠️ |

**读数口径**（与 SOLUTION_REVIEW §2.3 第 2 层一致）：
- SNR ≥ 10 dB：精度被距离量化残差 `round(D·fs/c)·c/fs − D` 决定，与 SNR 解耦
- SNR = 0 dB：RMSE ≈ 13 mm（约 2 个采样点），**仍满足 ±5 cm 工程指标**
- SNR = -10 dB：匹配滤波峰被噪声吸走，**物理不可用**

### 4.4 亚毫米精度路径（诚实披露：已放弃）
早期版本实现过"频域分数延迟 + 三点抛物线亚样本插值"，希望把精度压到亚毫米。经 5 轮诊断发现：
- 抛物线插值对 **δ 冲激**只有 ~0.1 样本残差（理论符合）
- 但对 **chirp 匹配滤波输出**，chirp 自相关主瓣非对称（线性调频的相位-时间耦合），抛物线拟合有 **~1 样本本质偏置**，比理论预期差一个数量级
- 用 16× 过采样的"真·延迟 0.25 样本 chirp"回归，抛物线估计偏置仍 +0.508 样本

结论：**本白皮书 v0.1 接受 7 mm 量化地板**，D3 真机实测阶段再评估是否引入 sinc 插值 / 复相关相位法 / 提高采样率。

### 4.5 D2 Arduino POC 现状
位置：`src/tests/test_acoustic_tdoa/`，单 sketch 通过 `#define ROLE_TX/ROLE_RX` 切换角色。

**已落地特性**：
- 参数与 D1 完全一致（48 kHz / 5 ms / 17–19 kHz / Hann / peak=28000）
- **定点相关**：int16×int16→int64 朴素滑动相关，单次 <3 ms @ 240 MHz，不依赖 FFT / 浮点栈
- **CFAR 检测判据**：主峰必须 ≥ 4× 于保护带外次峰，不依赖能量绝对值（避免早期版本用"经验阈值 20M"这种假设实现）
- **相对位移输出**：打印 `window_offset_samples` + 相邻两次差值 `rel_delta_mm`

**诚实披露的 POC 限制**（B1 不打补丁，留 D3 解决）：
- 当前 POC **无跨板硬同步**，RX 算到的 argmax 只是"chirp 在 30 ms 采集窗里的位置"，**不等于 TX→RX 绝对飞行时间**
- 因此 POC 只能输出**相对位移**（双手间距的相对变化），不能直接给绝对距离
- 要得到绝对距离，必须在 D3 阶段把 `esp_now_sync.h` 或一条 GPIO 同步线接进来，让 RX 知道 "TX 发出 chirp 的那一刻对应 RX 本地时钟 t=0"

### 4.6 同步抖动对绝对距离的物理限制
**关键物理事实**（声速 × 时间即距离，无规避空间）：
- 同步抖动 Δt → 距离误差 Δd = c · Δt，每 1 ms → 343 mm
- 这是 §2.1 验证层目标里"测距 ≤ 5 cm"的**上游硬约束**：允许的同步抖动 ≤ 5cm/343 m/s ≈ **146 μs**

三档同步方案的数量级对比：

| 同步方式 | 典型时间不确定度 | 对应距离误差 | 是否够用（5 cm 指标） |
|---|---|---|---|
| 裸 ESP-NOW 用 `millis()` 对齐 | 1–3 ms（毫秒级 OS 调度 + 无线排队抖动；Espressif 文档定性为"毫秒级" ） | 343–1029 mm | ❌ 差一个数量级 |
| ESP-NOW + RX 侧 `micros()` + 固定偏移校正 | 数百 μs（去掉 OS 调度抖动，仅剩无线层） | ~100–300 mm | ❌ 仍差 2-6× |
| **一条跨板 GPIO 硬触发线 + ISR 打戳** | ESP32 GPIO ISR 典型 μs 级响应（ESP-IDF `gpio_install_isr_service` 文档描述为"极低延迟"，具体 ISR-to-handler 延迟跟并发负载有关） | **μs 级 × 343 m/s ≈ 亚毫米** | ✅ 远超指标 |

> 上表"μs 级"保留**模糊量级**描述而非具体数字，是因为 GPIO ISR 响应时间在
> FreeRTOS 下受中断优先级、是否持有锁、缓存命中等多重影响，简单地写"< 20 μs"
> 会误导读者。真实数字要在 D3 阶段用**双板同一信号对打 GPIO + 逻辑分析仪**
> 测量，预期量级是 μs 级、远低于 146 μs 上限。

**结论**：**纯 ESP-NOW 同步不足以支撑绝对距离测量**，D3 必须配一条跨板 GPIO 硬触发线
（Master 发 chirp 前拉高 GPIO，Slave 用边沿触发 ISR 记 `esp_timer_get_time()`）。
硬件团队在 P2 阶段布板前需预留 1 条跨板 GPIO。

### 4.8 双向 RTT-TOF 技术原理详解

#### 4.8.1 为什么单向 TOF 不够

单向 TOF（Time-of-Flight）的原理是：TX 在 `t_send` 时刻发出 chirp，RX 在 `t_recv` 时刻接收到相关峰，则距离 `d = c × (t_recv − t_send)`。这里有一个致命前提：**TX 和 RX 必须共享同一个时钟**，否则 `t_recv − t_send` 里混入了两块晶振之间的频率差积累误差（clock offset）和相位差（phase offset）。

两块 ESP32-S3 各用自己的 40 MHz 主晶振（APB_CLK 80 MHz，供 `esp_timer_get_time()`/`millis()`），ESP-IDF 官方标注精度 < ±10 ppm。两颗晶振最坏情况下（一块 +10 ppm，另一块 −10 ppm）相对频差 20 ppm，每秒积累时钟偏差 20 μs → 距离误差 `343 m/s × 20 μs = 6.9 mm`，单次测距（~90 ms）内积累偏差 **20 ppm × 0.09 s = 1.8 μs → 0.6 mm**，在 7.15 mm 量化粒度内完全可忽略。但**跨板绝对时刻对齐**的问题更严重：两块板上电起点不同，`esp_timer` 的"零点"可能差数秒到数分钟，若运行 60 秒后才开始测距，最坏积累偏差 `20 ppm × 60 s = 1.2 ms`，对应 `343 m/s × 1.2 ms = 412 mm` 的距离误差——这才是单向 TOF 不可用的根本原因，不在于短期频率漂移，而在于**绝对时刻基准不同**。RTT-TOF 差分消去的正是这个绝对偏差 δ，与积累时长无关。

#### 4.8.2 双向 RTT-TOF 的数学推导

设两块板分别是 A（Master/右手）和 B（Slave/左手），各自维护本地时钟。定义：

```
t_A1  — A 发出 chirp 的时刻（A 的本地时钟）
t_B1  — B 收到 chirp 的时刻（B 的本地时钟）
t_B2  — B 发出 chirp 的时刻（B 的本地时钟）
t_A2  — A 收到 chirp 的时刻（A 的本地时钟）

τ     — 真实声学飞行时间（A↔B 单程）
δ     — A 和 B 时钟的固定偏差（B 的时钟 = A 的时钟 + δ，δ 未知）
T_proc — B 从收到 chirp 到发出自己 chirp 的处理延迟（B 本地可精确测量）
```

单向测量（A→B）：
```
t_B1 = t_A1 + τ + δ        ← 含未知时钟偏差 δ
```

单向测量（B→A）：
```
t_A2 = t_B2 + τ − δ        ← δ 符号相反
```

两式相加，δ 完全对消：
```
t_B1 + t_A2 = t_A1 + t_B2 + 2τ
→  2τ = (t_A2 − t_A1) − (t_B2 − t_B1)
→   τ = [(t_A2 − t_A1) − (t_B2 − t_B1)] / 2
→   d = c × τ
```

其中 `(t_A2 − t_A1)` 是 A 侧可观测的**往返时间**（round-trip time），`(t_B2 − t_B1)` 是 B 侧可精确计量的**转发等待时间** `T_proc`。A 只需要从 B 那里（通过 ESP-NOW）拿到一个标量 `T_proc`，就可以完全在自己的时钟域内完成计算：

```
d = c × [(t_A2 − t_A1) − T_proc] / 2
```

**关键结论**：只要 B 能精确计量自己的 `T_proc`（用本地 `esp_timer_get_time()`，精度 1 μs），且 A 能精确记录 `t_A1` 和 `t_A2`，则**两块板的时钟偏差 δ 和漂移率 Δf/f 完全被差分消去**，不影响测距结果。

#### 4.8.3 时序编排（一次测距的完整流程）

RTT-TOF 公式要求 `T_proc = t_B2 − t_B1` 中两个时刻必须在**同一时钟域**内计算。本设计规定：B 侧 `t_B1` 和 `t_B2` 均使用 `esp_timer_get_time()`（1 μs 分辨率），GPIO 触发线只作"采集开窗"信号，不参与 T_proc 计算。

```
A（Master）                                        B（Slave）
───────────────────────────────────────────────────────────────────
① A 记录 t_A1 = esp_timer_get_time()，拉高 GPIO_SYNC
                   ────── GPIO 上升沿 ──────>
                                               ② B ISR 触发：启动 I2S_NUM_1 DMA 采集窗口
                                                  （ISR 仅用于"开窗"，不参与测距计算）
③ A 向 I2S_NUM_0 写入 chirp PCM，DAC → 喇叭发声
                   ────── 声波（飞行时间 τ）──────>
                                               ④ B INMP441 → I2S_NUM_1 DMA 持续采集
                                               ⑤ B 相关器在采集窗内找到匹配峰，
                                                  记录 t_B1 = esp_timer_get_time()
                                                  （声学峰对应的本地时刻，B 时钟域）
                                               ⑥ B 等待固定静默 ≥ 多径尾巴衰减时间
                                               ⑦ B 记录 t_B2 = esp_timer_get_time()，
                                                  向 I2S_NUM_0 写入 chirp PCM，发声
                   <────── 声波（飞行时间 τ）──────
⑧ A INMP441 → I2S_NUM_1 DMA 持续采集
⑨ A 相关器找到匹配峰，记录 t_A2 = esp_timer_get_time()（A 时钟域）
                   <── ESP-NOW 回传 T_proc ────
                                               B 把 T_proc = t_B2 − t_B1 回传给 A
                                               （两者均为 esp_timer，同一 B 本地时钟，自洽）
⑩ A 计算 d = c × [(t_A2 − t_A1) − T_proc] / 2
⑪ A 把距离观测量写入下一帧 HandFrame 的 dist_in 字段
```

**GPIO 触发线的作用边界**：GPIO 上升沿仅通知 B"A 即将发声，请开好采集窗口"，防止 B 的 DMA 缓冲区在 chirp 到达前未启动而错过前沿。GPIO ISR 到 DMA 首样本之间的固定延迟、以及 DAC 建立时间（MAX98357A 典型 7.5 ms turn-on time）和喇叭机械惯性，都是**两侧对称的确定性偏移**，在 D3 台架自校准时用已知距离整体补偿，不引入随机误差。

#### 4.8.4 采样率与精度预算

| 参数 | 数值 | 说明 |
|------|------|------|
| fs（采样率） | 48 kHz | INMP441 默认，与 TTS I2S 分开用 I2S_NUM_1 |
| 单样本时间 | 1/48000 ≈ 20.8 μs | |
| 单样本距离量化粒度 | c/fs = 343/48000 ≈ **7.15 mm** | 绝对精度下限，SNR→∞ 也消不掉 |
| GPIO 触发抖动（预期） | μs 量级 | 远小于 20.8 μs 的采样粒度，不是瓶颈 |
| T_proc 精确计量误差 | ≤ 1 μs（`esp_timer_get_time()` 分辨率） | 对距离的贡献：343 mm/s × 1 μs ÷ 2 ≈ 0.17 mm，可忽略 |
| **总精度下限** | **7.15 mm（≈ 0.5 个采样样本）** | SNR ≥ 10 dB 时 D1 仿真验证 RMSE ≈ 0.21 mm（量化残差主导） |

精度瓶颈不在同步，而在**声学采样率**。提升精度的唯一硬路是提高 fs（96 kHz → 3.57 mm）或引入复相关相位法（见 §4.4 讨论，chirp 相关峰非对称性使抛物线插值失效，复相关是备选但更复杂）。

### 4.9 实际工程困难评估

以下是从 D3 真机测试到 D4 双向 RTT 可能遇到的**主要工程挑战**，按难度和风险排序，每项都给出当前方案中的缓解措施或一票否决条件。

#### 4.9.1 多径反射与伪峰（高风险）

**问题本质**：室内墙面、桌面、人体躯干都会产生 chirp 的反射回波。反射回波比直射波晚到 `Δt = 2×extra_path / c`，例如墙面距手 0.5 m 的旁路多径会产生 `2×0.5/343 ≈ 2.9 ms` 的延迟，即 140 个样本后出现一个强度接近直射波的伪相关峰。如果 CFAR 判据失效，匹配滤波器会错误地把多径峰当作直射峰，造成**距离跳变 50–300 mm**。

**当前缓解措施**：
- **30 ms 采集窗**：直射波在 10 cm–1.5 m 范围内飞行时间 ≤ 4.4 ms，多径通常延迟 > 2 ms，有时间分离
- **CFAR 判据**：主峰 ≥ 4× 次峰，要求直射波在 SNR 上显著压制反射波
- **17–19 kHz 的选频效果**：空气吸收系数随频率升高而增大（ISO 9613-1），超声频段的多径反射波在每次壁面反射时损耗更多能量；室内常见材料（软装、人体）在高频段的吸收系数也更高，有助于抑制多径幅度——但具体降低幅度依赖场地材质，**本文档不给假设数字，留 D3 实测**

**残余风险**：
- 手握拳时，手掌本身构成 **凹面反射腔**，近距离（< 20 cm）的自身反射可能比对侧手的直射波还强，是 D3 阶段最主要的实验变量
- 混响较强的场景（硬地板 + 白板 + 玻璃）中，CFAR 4× 阈值可能不够，需要提高到 6× 或 8×，但同时增加了漏检率
- **当前文档不给"多径抑制 dB 数"**，这是一个只能在真实场景中实测的变量，D3 必须在有代表性的演示场地（比赛现场类似环境）测量，而不仅仅是安静实验室

#### 4.9.2 同频干扰：双手同时发声（高风险）

**问题本质**：双向 RTT 要求双方都有发声能力，但如果 A 和 B 同时发 chirp，接收到的信号是**两个 chirp 的叠加**，匹配滤波器无法区分是对面发来的直射波还是自己刚发出的信号（即使有延迟差，重叠区会造成相关峰畸变）。

**当前方案（TDM 时分复用）**：
```
时间轴：
[A 发][──── 静默 ────][B 发][──── 静默 ────][A 发] ...
  5ms       ≥25ms     5ms       ≥25ms
```
- A 发 chirp → 静默等待 B 的回波（≥ 30 ms，覆盖最大量程 1.5 m 的飞行时间 4.4 ms + 多径尾巴）
- B 收到 A 的 chirp 后，等待固定 `T_proc`（如 20 ms），再发自己的 chirp
- A 在 B 发之前静默，A 的麦克风接收 B 发的 chirp

**时序约束**：
```
T_proc ≥ T_tail_reverb ≈ 10–20 ms（混响尾巴衰减到 CFAR 阈值以下所需时间）
一轮测距总时长 = 5ms（A发）+ T_wait_A（≈30ms）+ T_proc（≈20ms）+ 5ms（B发）+ T_wait_B（≈30ms）≈ 90 ms
```
因此 20 Hz（50 ms/帧）的测距节奏目前**无法达到**，双向 RTT 的实际节奏约 **10 Hz（100 ms/轮）**。识别层在 dist_in 缺测的帧用上一帧的值填充（Zero-Order Hold），或降采样到 10 Hz 对齐。

**双频方案（备选，复杂度高）**：A 用 17–18 kHz，B 用 18–19 kHz，匹配滤波器各自带通滤波后分别检测，理论上可以同时发收。两个频带仅在 18 kHz 边界点接触（不重叠），**理论上近似正交**（互相关接近零）；但 18 kHz 处的共享边界点会产生有限的互相关残差，加之两条链路各自的硬件频响不对称，实际互干扰量**需要台架实测标定**。**本白皮书 v0.1 暂不采用双频，留 D4 阶段如果 TDM 时序不够再评估。**

#### 4.9.3 喇叭和麦克风的硬件非理想性

**MAX98357A + 小喇叭在 17–19 kHz 的频响问题**：
- 小尺寸全频喇叭（40 mm 左右，4Ω 3W）通常在 **5–8 kHz 就开始明显滚降**，到 15–20 kHz 范围内衰减已相当严重；具体衰减量因型号差异较大（额定频响通常写到 15–20 kHz，但末端已是−10 dB 以下），**本文档不给无型号支撑的数字**，以 D3 台架实测值为准
- 这意味着实际发出的 17–19 kHz 声压相比中频显著偏低，有效 SNR 比 D1 仿真（假设理想平坦链路）要差，具体差多少留实测
- **D3 一票否决条件**：在 50 cm 距离下，CFAR 检测成功率 < 90%，或测得 SNR < 0 dB（匹配滤波峰被噪声完全淹没），则需要更换高频响应更好的发声器件（如压电超声换能器，中心频率 20–40 kHz，带宽更窄但发射效率更高）

**INMP441 在 17–19 kHz 的响应问题**：
- INMP441 数据手册标称平坦频响 60 Hz–15 kHz（±3 dB 以内）；15 kHz 仍在平坦响应区间内，**不是** 15 kHz 处有大幅下降——而是 **15 kHz 以上**才开始明显滚降，17–19 kHz 处已超出设计频段，灵敏度下降量无数据手册支撑，**实测时以台架量化为准**
- 总体链路损耗（喇叭高频衰减 + 麦克风 15 kHz 以上滚降 + 空气传播 1.5 m @ 0.4 dB/m）叠加后，实测 SNR 相比 D1 仿真（假设理想平坦链路）预计有明显下降，**具体数值留 D3 台架实测后填入**
- **缓解思路**：① 发射幅度已到 int16 峰值 28000（接近满幅），无法再提；② 接收侧加 17–19 kHz 带通 FIR 滤波抑制 TTS 播放残留噪声；③ 若 SNR 不足，chirp 时长从 5 ms 延长到 10 ms 可提高匹配滤波处理增益约 3 dB（处理增益 = 10log₁₀(B×T)，T 翻倍时增益 +3.01 dB）

**DAC 建立时间与喇叭机械惯性**：
- MAX98357A 有 Turn-On Time（数据手册标注典型值 **7.5 ms**）；I2S 首帧写入到实际声波辐射之间还叠加喇叭音圈的机械惯性延迟（锥盆运动），两者合计构成一个固定的发射侧延迟
- 这个延迟是**确定性的固定偏移**（对所有测距帧一致），通过 D3 阶段台架自校准（已知距离 → 反算固定偏移）可以整体补偿，不引入随机误差

#### 4.9.4 TTS 与 chirp 共用 I2S_NUM_0 的冲突

**问题本质**：MAX98357A 当前挂在 `I2S_NUM_0`，TTS 播放和 chirp 发射都需要独占 I2S 总线。如果正在播报 TTS 时触发了测距轮次，或者测距 chirp 播放时 TTS 队列来包，将产生**I2S 资源竞争**。

**分析**：
- TTS 播报是低频事件（每次手势触发一次，持续 0.5–2 s），在 TTS 播报期间，手势已经锁定不再触发新识别，因此测距轮次可以在 TTS 期间继续（发 chirp 并不影响语音理解）
- 但同一 I2S 总线无法同时发 TTS PCM 和 chirp PCM
- **方案**：TTS 播报期间暂停测距（测距频率本已是辅助特征，短暂空缺不影响识别），TTS 结束后恢复；或在 TTS 播报时改用 BLE 广播距离占位符（上一帧有效值）

#### 4.9.5 单核/双核 FreeRTOS 任务优先级竞争

**问题本质**：双向 RTT 需要同时运行以下任务：
- I2S_NUM_0 的 chirp 发射（定时精度要求 < 1 ms）
- I2S_NUM_1 的连续采集（丢帧即漏检）
- 匹配滤波计算（< 3 ms @ 240 MHz，但需要 CPU）
- ESP-NOW 收发（T_proc 回传，WiFi/BT 共享射频）
- ESP32-S3 双核：Core 0 跑 WiFi/BT 协议栈，Core 1 跑用户任务

**缓解措施**：
- chirp 发射和 I2S 采集用 DMA，不占用 CPU
- 匹配滤波绑定到 Core 1（`xTaskCreatePinnedToCore`），优先级高于 LLM/TTS
- ESP-NOW T_proc 回传包极小（4 字节 uint32），延迟不敏感

**残余风险**：WiFi 和 I2S 采集同时工作时，WiFi SDIO 中断可能抢占 DMA 写入，导致 I2S 采集帧出现**气泡（silent frames）**，造成匹配滤波窗口内有零值填充，相关峰变形。需要在 D3 实测时用示波器或逻辑分析仪确认 I2S 数据完整性。

#### 4.9.6 手势运动导致的多普勒频移

**问题本质**：手势识别期间双手可能以 0.5–2 m/s 的速度相向/相背运动，chirp 飞行途中手的位移为 `v × τ ≈ 1 m/s × 5 ms = 5 mm`。此外，运动引起的**多普勒频移** `Δf = 2v/c × f_center = 2 × 1/343 × 18000 ≈ 105 Hz` 会使接收到的 chirp 频率轻微拉伸或压缩。

**影响评估**：
- **位移偏差**：`v × τ = 1 m/s × 5 ms = 5 mm`，小于 7.15 mm 量化粒度，引入 < 1 个样本的系统偏差，可忽略
- **多普勒频移对匹配滤波峰的影响**：频移量 `Δf/B = 105 Hz / 2000 Hz = 5.25%`，即接收到的 chirp 频率被拉伸约 5%。匹配滤波输出峰值损耗（mismatch loss）与 `(Δf × T)²` 成比例，`Δf × T = 105 Hz × 5 ms = 0.525`，对应峰值损耗约 `(0.525)² / 3 ≈ 0.09`，即 < 0.5 dB。峰值位置偏移量约 `Δf/( B/T ) = 105/(2000/5ms) = 0.26` 个样本 ≈ 1.85 mm，仍在量化精度 7.15 mm 以内
- **结论**：在 v ≤ 2 m/s、chirp 参数 5 ms / 2 kHz 条件下，多普勒效应引起的测距误差 < 2 mm，在 7.15 mm 量化精度内可忽略，**无需专门补偿**

#### 4.9.7 综合风险评估矩阵

| 困难项 | 风险等级 | 缓解措施 | D3 一票否决条件 |
|--------|---------|---------|----------------|
| 多径反射伪峰 | 🔴 高 | CFAR 4× + 30 ms 窗 | 演示场地 CFAR 成功率 < 90% |
| 双手同频干扰 | 🔴 高 | TDM 时分，T_proc ≥ 20 ms | 无法达到 10 Hz 测距节奏 |
| 喇叭高频响应不足 | 🟡 中 | 台架 SNR 实测 | 50 cm SNR < 0 dB（完全失效） |
| INMP441 高频衰减 | 🟡 中 | 带通 FIR + 延长 chirp | 同上，与喇叭联合评估 |
| TTS 与 chirp 资源竞争 | 🟢 低 | TTS 期间暂停测距 | 不构成否决，可接受 |
| FreeRTOS 任务竞争 | 🟢 低 | Core 1 绑定 + DMA | I2S 采集丢帧率 < 1% |
| 多普勒频移 | 🟢 低 | 无需缓解 | 不适用 |
| DAC/喇叭固定延迟 | 🟢 低 | 台架自校准一次补偿 | 不适用 |

**D3 的核心任务**就是把 🔴 两项高风险在真实硬件上量化：在有代表性的演示场地（非消声室）测量 CFAR 成功率和 TDM 下的实际测距 RMSE。如果两项都满足指标，D4 才推进双向 RTT 闭环。

## 5. Layer 3：识别 — 双流 1D-CNN

### 5.1 输入张量

**硬件配齐度与张量维度的对应关系（设计目标 vs 当前实际）**：

| 通道 | 设计目标维度 | **当前实际维度（B1 阶段）** | 说明 |
|---|---|---|---|
| 左手 IMU6 | (T, 6) | **(T, 6)** ✅ | Slave 板 MPU6050 已接（P1 待双板实测） |
| 左手 Flex5 | (T, 5) | **(T, 0)** ❌ | Slave 无弯曲传感器，该通道全部填 -1 |
| 右手 IMU6 | (T, 6) | **(T, 6)** ✅ | Master 板 MPU6050 已接 |
| 右手 Flex5 | (T, 5) | **(T, 1)** ⚠️ | 仅拇指 1 路已接；其余 4 路填 -1；全 5 路待采购补齐 |
| 相对距离 | (T, 1) | **(T, 1)**，值全为 -1 | INMP441 未到货，P4 阶段接入前全部用 -1 占位 |

**当前实际总维度**：`C_total = 6 + 0 + 6 + 1 + 1 = 14`（设计目标为 23）

**B1 阶段训练策略**：使用当前实际维度 14 训练 baseline 模型（填 -1 的通道仍保留维度，网络权重适应占位符输入）；待硬件齐套后，重新训练全 23 维正式模型，两版权重不兼容，届时重新导出 Edge Impulse 库。

每一次推理的输入是**时间对齐后**的双手窗口，时长 1 秒（20 帧）：

```

 ├── 左手 Flex5 (T, 5)
 ├── 右手 IMU6  (T, 6)

【B1 当前实际】shape = (T=20, C_total=14)
```

### 5.2 网络拓扑（与 SOLUTION_REVIEW §2.3 第 3 层一致）

```python
left_in  = Input((20, 11))   # IMU6 + Flex5
right_in = Input((20, 11))
dist_in  = Input((20, 1))

# 主干
left_f  = Conv1D(32, 3) → Conv1D(64, 3) → GAP    # (64,)
right_f = Conv1D(32, 3) → Conv1D(64, 3) → GAP    # (64,)

# 显式协同特征
cross = Concat([
    abs(left_in - right_in),      # 对称性
    left_in * right_in,           # 协同性
    dist_in                        # 相对距离（声学来源）
])
cross_f = Conv1D(16, 3) → Conv1D(32, 3) → GAP   # (32,)

logits = Dense(N_classes, softmax)(Concat([left_f, right_f, cross_f]))
```

**设计动因**：
- 双流而非单流 concat：保留单手语义通路，便于做"左/右手独立 F1"监控
- Cross-stream 用**手工先验**（差、积、距离）而非纯学习：参考 ST-GCN / MS-G3D 的经验，在数据量有限时（竞赛场景单人打每类 50 次 = 2500 样本）手工特征更稳
- 距离通道单独喂给 cross 而非拼到单手 Flex：距离是"两手的属性"而非"某只手的属性"，拓扑上更干净

### 5.3 推理预算（目前是**规划预估**，非实测）

**重要前置**：截至 B1 成文时，`src/LingxiGlove_Main/gesture_recognizer.cpp` 里真正
落地的是 `RuleBasedRecognizer`（规则识别器），**还没有任何训练过的 CNN 跑在端侧**。
因此下表所有数字都是"规划依据"，不是"已实测"。

| 子模块 | 参数量 | 推理延迟 | 依据 |
|---|---|---|---|
| 单手 1D-CNN（INT8 量化） | ~12 K | ~15 ms | `doc/Edge_Impulse_ESP32_S3_训练指南.md` §7.1 给出的 Edge Impulse 官方 INT8 对照表典型值（FP32 → INT8 的 ~40% 加速是 EI 官方公开数据，具体绝对值要看模型结构，P1 训练后以 Model performance 页实测为准） |
| 双流 + cross 融合版 | ~30 K | ~40 ms | 保守估计：双流两条骨干 + 一条 cross 骨干 ≈ 3× 单手计算量。真机实测留 P4 填入 |
| TDOA 相关器 | n/a | ~3 ms（估算） | 288k MAC / 240 MHz ≈ 1.2 ms 纯 ALU，考虑流水线停顿和 I2S 搬运取 2-3× 余量。真机实测留 D3 填入 |
| 同步对齐（环形缓冲最近邻） | n/a | <1 ms | O(log N) 二分，N ≤ 100（约 5 秒历史帧） |

**端到端上界** ≈ 40 + 3 + 1 = **44 ms < 50 ms 帧窗**，数量级有余。
但**任一真实测量出来显著偏离这个预估 2×以上，都应当触发架构回炉**——
比如双流推理真机实测 90 ms，就必须转向模型剪枝 / 双核分工 / 降帧率，
而不是假装还能继续。

### 5.4 训练数据策略（规划 · 当前数据集 = 0 样本）

**前置声明**：B1 成文时仓库内**没有任何采集到的训练数据**，也没有 CNN 权重。
以下策略是 P1/P4 阶段的规划，不是"已经这么做了"。

- 每类每人采 50 次，左右手各打一次 → 样本量 = 类数 × 人数 × 100
- **水平翻转增强**：左手样本可通过镜像生成"虚拟右手样本"，等价于免费 ×1.5 数据量
- **时间抖动增强**：± 2 帧随机平移，覆盖手势起止时刻不准的噪声
- 评估：分别算 `F1_left / F1_right / F1_bimanual`，任一低于整体 5 个百分点则回炉
- 采集执行路径：走 MVP 已落地的"采集模式"串口命令（见 `src/LingxiGlove_Main/README.md` 的
  `c` 命令，打 CSV 到 Serial），再用 `tools/` 下的脚本转 Edge Impulse 数据集格式（脚本 P1 再写）

### 7.2 关键路径与"一票否决"节点

```
已完成: A1 (同步接口) ──┐
                        │
已完成: D1 (仿真) ───D2 (单向 POC) ───┐
                                      │
                                      ▼
                D3 (真机 chirp 收发 + GPIO 硬同步)   ← go/no-go #1
                                      │
                                      ▼
                D4 (双向 RTT-TOF，抵消时钟偏差)       ← go/no-go #2
                                      │
                                      ▼
                P2 (双板实测) ── P4 (双流 CNN) ── P5 (云端)
```

**D3 是第一个一票否决节点**：如果真机实测下，引入一条跨板 GPIO 硬同步后
（见 §4.6），单向链路的绝对距离 RMSE 仍明显大于 15 mm，则说明 MAX98357A 喇叭
在 17–19 kHz 的响应或 INMP441 的模拟前端引入了无法忽略的色散/群延迟，
此时要么切换器件、要么放弃 TDOA、改投 UWB（SOLUTION_REVIEW §2.3 候选 A）。

**D4 是第二个一票否决节点**：双向 RTT-TOF 依赖"两方几乎同时各发一次 chirp
且互不干扰"的调度，如果 D4 实测双向信号互扰严重（由于两只手套在空间上
相距仅 10 cm–1.5 m，同频 chirp 可能重叠），就要引入 TDM（时分复用）或双频
（例如一方 17–18 kHz、另一方 18–19 kHz）分离。TDM 会把每次有效测量的
延迟翻倍，双频则要生成两份模板。哪一种更优要靠 D4 实测才能判断。

这两个决策点**白皮书显式写出是为了让项目有明确的 go/no-go 预案**，
而不是等答辩前被问到"如果你们真机做不出来怎么办"才临场应对。
